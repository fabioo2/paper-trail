# Stage 0 test plan: acceptance criteria to tests

Written by the test author on 2026-11-06, before any implementation exists. All tests here are expected to fail until Stage 0 is built. Source of truth: `docs/PLAN.md` §1.7 and §2.

## Suites and how they run

Every command runs in a container through `make`. Nothing runs on the host.

| Suite | Location | Marker | Runs in | Make target |
|---|---|---|---|---|
| Unit | `tests/unit/` | none | `dev` | `make test`, `make test-unit` |
| Contract | `tests/contract/` | none | `dev` | `make test`, `make test-unit` |
| Integration | `tests/integration/` | `integration` | `dev` | `make test`, `make test-integration` |
| End to end | `tests/e2e/` | `e2e` | `dev` | `make test` |
| Repository checks | `tests/repo/` | `repo` | `dev` | `make test` |
| Frontend unit/component | `frontend/src/**/*.test.ts(x)` (jsdom) | n/a | `frontend` | `make fe-test` |
| Frontend tooling | `frontend/tests/tooling/*.test.ts` (`@vitest-environment node`) | n/a | `frontend` | `make fe-test` |
| Smoke | `scripts/smoke.sh` | n/a | `smoke` (curl image) | `make smoke` |
| Container checks | `tests/container/run.sh` and `check_runtime_image.py` | n/a | `container-checks` (docker CLI image) | `make container-checks` (part of `make ci`) |

`tests/conftest.py` registers the `integration`, `e2e` and `repo` markers and applies them by directory, so `--strict-markers` holds without per-test decorators. `make test-unit` is `-m "not integration and not e2e and not repo"`.

Test support files the plan assigns to tests (written here, not by the implementer): `tests/conftest.py`, `tests/support.py`, `tests/fakes/{clock,health}.py`, `tests/repo/{conftest,makefile_parser}.py`, `frontend/src/test/{setup.ts,render.tsx,match-media.ts,text.ts,msw/server.ts,msw/handlers.ts}`, `frontend/tests/tooling/paths.ts`, `scripts/smoke.sh`, `tests/container/{run.sh,check_runtime_image.py}`.

## What the implementer must provide for these tests to run

The plan leaves some details open. The tests settle them as follows. Each one is the smallest reasonable reading of the plan.

Backend

- `Settings` has `build_sha: str | None = None` (env `PAPER_TRAIL_BUILD_SHA`, set by the image). §2.3 sets this env var for the health endpoint, and S0-AC-14 forbids reading `os.environ` anywhere but the CLI, so it has to be a setting. It is listed in `.env.example` like every other setting.
- `Settings.database_path` is resolved by a validator, so `Settings().database_path == Path("/data/paper_trail.db")`.
- `PAPER_TRAIL_WORKER__POLL_INTERVAL_S` accepts 0.1 to 60 inclusive.
- `DatabaseHealthProbe(engine)`: the constructor takes the engine.
- `HeartbeatFile.beat()` creates the parent directory. The worker CLI is tested on an empty data dir.
- `WorkerRunner.run()` restores the previous SIGTERM/SIGINT handlers on exit. Otherwise a test process stays unkillable.
- Worker lifecycle log events are `worker.stopping` and `worker.stopped`. HTTP access lines are `http.request`.
- The OpenAPI document contains only `/api/*` paths, and every operation declares a `500` `application/problem+json` response. `info.title` is `Paper Trail`.
- With JSON logging, exceptions are rendered into an `exception` key on the same line.
- Every response carries `X-Request-ID`, including 404, 500 and SPA responses.
- `paper-trail openapi` and `paper-trail serve` build the container without opening the database. The engine connects lazily.
- `migrations/env.py` must not call `logging.config.fileConfig`, because alembic lines must stay JSON (S0-AC-15).
- Dev dependency group adds `pyyaml` and `types-pyyaml`, which the repository checks use.

Make and compose

- A `container-checks` Make target runs `tests/container/run.sh` in a compose service `container-checks` (profile `dev`). That service uses a pinned `docker:<x.y.z>-cli` image, mounts `/var/run/docker.sock`, mounts the repo at its host path (`${PWD}:${PWD}:ro`, `working_dir: ${PWD}`) and runs the script. `make ci` depends on `build check smoke container-checks`. This is where the plan's "runtime image size budget" lives.
- The `smoke` service runs `/scripts/smoke.sh` from `./scripts:/scripts:ro`.
- Every target is `.PHONY`, `.DEFAULT_GOAL := help`, and help is generated from `## ` comments.

Frontend

- Named exports: `createAppRouter({ queryClient, history })` and type `AppRouter` from `@/app/router`; `AppProviders({ queryClient, children })` from `@/app/providers`; `createQueryClient()` from `@/app/query-client`; `ConnectionIndicator` from `@/components/layout/connection-indicator`; `apiClient`, `unwrap(promise)` and `ApiError { status, problem? }` from `@/api/client`.
- `AppShell` renders a `<main>` landmark. Each page's empty state renders a heading inside it. The not-found heading matches `/not found/i`.
- The theme toggle is a `button` whose accessible name contains "theme". The skeleton is the shadcn v4 `Skeleton`, which emits `data-slot="skeleton"`. The "Connected"/"Offline" text is `sr-only`.
- `src/vite-env.d.ts` types `VITE_API_BASE_URL`. `vite.config.ts` holds the Vitest config (`environment: "jsdom"`, `setupFiles: ["./src/test/setup.ts"]`).
- `tsconfig.node.json` includes `tests/**/*.ts`, so the tooling tests are type-checked and type-aware ESLint can see them.
- The ESLint flat config ignores `dist/` and `src/api/schema.d.ts`.
- devDependencies: `vitest`, `@vitest/coverage-v8`, `jsdom`, `@types/jsdom`, `@types/node`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `msw`.
- jsdom pitfall: Node's `fetch`/`Request` reject relative URLs. A `baseUrl` of `""` must therefore resolve to `window.location.origin` at runtime (still same-origin), or `openapi-fetch` throws under test. Do not pass TanStack Query's `AbortSignal` (jsdom) into Node's `Request`.
- `import-linter`: rule 4 (agents/tools) is tested by creating those packages in a scratch copy. If import-linter cannot reference packages that do not exist yet, model them as optional layers (`(paper_trail.agents)`) or add the contract with `ignore` semantics. The fixture test must still fail on the planted import.

## Criteria not fully automatable

- **S0-AC-01** (`make check` exits 0 on a clean checkout with only Docker, Make and Git). This is the gate itself, so it is verified by running `make check` (locally and in CI). A test inside the gate cannot assert that the gate passed. The tests assert its composition.
- **S0-AC-11** (LAN half). Reaching `http://192.168.1.10:8420/api/health` from another LAN device or the WireGuard phone requires a second machine and the owner's `.env` (`PAPER_TRAIL_BIND_ADDR=192.168.1.10`). It stays a manual checklist item for the stage PR. `scripts/smoke.sh` automates the in-network part.
- **S0-AC-39** (GPU runtime). The Ollama container is never pulled or run here: the LLM host is a separate Windows PC that is never contacted. The compose file is validated statically and with `docker compose config` only. GPU passthrough, model pulls and the Windows firewall rule are checked manually on the GPU PC.
- **S0-AC-36** (README and CONTRIBUTING content, prose quality, diagram accuracy). The tests only check that every linked path exists; that the required content is there and reads well is for the reviewer.
- Touch-target size (44×44 px, §2.10) and token-only colours have no automated check, because jsdom does no layout. The reviewer checks them.
