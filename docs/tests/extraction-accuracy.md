# Extraction accuracy test plan: acceptance criteria to tests

Written by the test author on 2026-11-08, before any implementation exists. Source of truth: `docs/plans/extraction-accuracy.md` (approved 2026-11-08), §3 EA-AC-01..14. Suites, markers, fakes and Make targets are the agent-core slices' (`docs/tests/agent-core-A.md` to `agent-core-D.md`).

**No test touches a real model.** The LLM is `ScriptedLlm` (unit, integration) or the scripted fake Ollama on 127.0.0.1 (CLI). The OCR confidence that drives vision first is set on the harness's `FakeOcr` (`harness.ocr.mean_confidence`).

## How the tests fail before the implementation

`make test-fast` on 2026-11-08 with only the test author's changes: 1586 passed, 47 failed, 12 errors. `make lint` passes, import contracts included.

- **Collection errors (12)**: the six new modules import names that do not exist yet (`paper_trail.domain.rules.printed`, `PrintedValueError`, `PrintedExtraction`, `ANSWER_MODELS`, `effective_limits`, `first_attempt`, `split_item_code`). `test_routing.py` builds `GraphLimits(..., vision_first_below=0.0)` at module level, so it errors once per xdist worker (6) with `TypeError: unexpected keyword argument 'vision_first_below'`. Other suites still run (xdist keeps going past a module that fails to collect).
- **On their assertions**: the missing `extraction/v2` and `vision/v1` prompts (`LookupError`), `RenderedPrompt.example_texts`, the vision request still on `extraction/v1` with OCR text and feedback, vision answers scripted as printed values that `ExtractionOutput` rejects, the new settings and defaults, the date rule, the graph snapshot's new edge.
- `mypy` reports only names that do not exist yet (plus two `Any` returns that resolve with them).

End to end (`pytest tests/e2e tests/repo`): 442 passed, 7 failed: the production-default CLI runs (`test_cli_vision_enrichment.py` x6: v2 answers, two vision attempts, `--prompt-version v1`) and the real `process` process (`test_cli_processes.py`, a printed answer under the v2 default).

## Test support changed by the test author

- **`tests/agent_harness.py`**: `agent_settings(..., extraction_version="v1", vision_first_below=None)`. The graph suites written before this change keep the text prompt on `extraction/v1` and script `extraction()` (integer cents), as slice D kept vision off for slices A-C. Tests of this change pass `extraction_version="v2"`. The vision attempt always uses `vision/v1` (printed values), so every suite that scripts a vision answer now scripts `printed_extraction()`. `vision_first_below` is only sent when given (the field does not exist yet).
- **`tests/e2e/agent_cli.py`**: `configure_cli` also pins `PAPER_TRAIL_PROMPTS__EXTRACTION_VERSION=v1` unless `slice_d=True` (production defaults: v2, two vision attempts, enrichment).
- **`tests/extractions.py`**: `printed_extraction()` / `printed_inconsistent_extraction(line=3|1)` (the default receipt as printed values, with the same issues as `inconsistent_extraction`), `printed_fixture(name)`.
- **`tests/data/extraction/costco_printed.json`**: the 2026-11-05 Costco photo as a good model would print it: 22 lines (kimchi 10.99, pork ramen `20.19 A`, dish pacs `18.99 A`, PJ `29.99 A`, `MULTIPLE 6.00-` as a discount, 5 x CHOC PISTACH 16.99 each followed by `TPD/1362394 4.00-` read as an *item*, 2 x GOLD KIWI 15.99 each followed by `4.00-`, doughnuts 10.99, eggs 8.99, `1281 1% MILK` 6.09), subtotal 189.16, taxes `["5.21", "8.82"]` = 14.03, total 203.19, date `2026/11/05`. Item codes and the card (`0000`) are synthetic.
- **`tests/data/extraction/superstore_printed.json`** (stretch S1): `26/11/02`, a multi-buy whose `2/$10.00 10.00` covers two products (first `amount: null`), a weighed line `0.460 kg @ $3.31/kg 1.52`, promo text `$1.29 lmt 4` as a unit price, `3/$10.00` over 10.00, a `1.00-` read as an item; 21.81 + 0.65 = 22.46.

## Changes to existing tests

- `test_config_agent_core.py`: defaults `psm=6`, `max_vision_attempts=2`, `extraction_version="v2"`; the environment test now sets the old values (psm 4, v1) to prove they still read.
- `test_config_agent_core_d.py`: the default vision limit is two attempts. `test_cli_agent_core.py`: `with_flags(...).max_vision_attempts == 2`.
- `test_routing.py`: every `GraphLimits` passes `vision_first_below=0.0`; `route()` is unchanged.
- `test_graph_shape.py`: edge `("read", "extract_vision")` added; nothing else (EA-AC-14).
- `test_dates.py`: `"11/01/2026 14:32"` moved from "unparseable" to 2026-11-01 (plan 2.3: a trailing time is ignored).
- `test_vision_fallback.py`: the vision request uses `vision/v1` (system + one user message, no examples, no OCR text); vision answers are printed values; `test_ac_d_01_the_vision_attempt_carries_the_latest_issues` and `..._without_feedback_the_vision_attempt_gets_the_generic_line` are replaced by the EA-AC-09 clean-prompt versions; `test_every_vision_attempt_allowed_is_made` and the reprocess test script each reply explicitly.
- `test_transport_equivalence.py` (`vision_and_enrichment`), `integration/test_vision_enrichment_sqlite.py`, `test_log_privacy.py` (slice D): the vision reply is `printed_extraction()`.
- `e2e/test_cli_vision_enrichment.py`: production defaults now mean printed answers and two vision attempts (4 calls, `max_vision_attempts == 2`); `e2e/test_cli_processes.py`: the real `process` answers `printed_extraction()`.

## Choices where the plan left room

1. **Costco fixture: seven `4.00-` lines, 22 lines** (the owner's evidence: 5 x CHOC PISTACH + 2 x GOLD KIWI), not the plan's "19 lines, six `4.00-`"; the totals match the paper (189.16 / 14.03 / 203.19).
2. **Trailing time**: `11/01/2026 14:32` was pinned as unparseable; plan 2.3 makes a trailing time ignorable, so that row now expects 2026-11-01.
3. **Leak guard and generic lines**: a line whose alias is generic (`is_generic_alias`, e.g. `INSTANT SAVINGS`, which is also in v1 example 03) never counts as a copy. Without this the guard would refuse real receipts (and the existing matching suite's `mixed_lines_extraction`). The guard applies to v1 too (the real leak was a v1 example).
4. **The `read` edge's ROUTE event** is emitted only when going vision first, named `extract_vision` (like the supervisor's ROUTE events, named after the target). A text-first photo emits none, so every existing route list stays as is.
5. **First vision attempt with feedback off** gets no generic line either: clean means clean; a vision retry gets the generic line.
6. **Vision tag without examples**: not pinned (`vision/v1` or `vision/v1+noex`); either way the request is system + user.
7. **S1 tested through `PrintedExtraction.to_output()`**, not `share_amounts` directly: the plan does not fix the domain-side line type `share_amounts` takes. Tests are in their own stretch files rather than `test_printed.py` / `test_normalization.py`, so each stretch can be cut by deleting one file.
8. **`PrintedValueError`** is imported from `paper_trail.domain.errors` (plan §4: "`PrintedValueError` (domain/errors)"). Messages are checked for the field (`line N` 1-based, `amount`, `total`, `subtotal`, `tax`) and the printed text in double quotes, not for wording.
9. **`parse_quantity("2x")` is 2** and `"x"` alone is an error; `parse_unit_price("lmt 4")` is None.
10. **Empty `taxes`**: the tax of an answer with no printed tax is not pinned (None or 0 both validate).
